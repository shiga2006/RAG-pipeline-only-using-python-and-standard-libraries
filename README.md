# Employee Knowledge Assistant - retrieval-only RAG prototype

No LLM, no hosted/local model, no vector DB. Python + NumPy; parsers only for PDF/DOCX/PPTX.

## Run it
```bash
pip install -r requirements.txt
python make_kb.py          # (optional) regenerates the sample KB in kb/ from kb_content.py
python search.py           # interactive; or: python search.py "how many sick days do I get?"
python test_queries.py     # 20 labelled queries -> results/test_results.md
python evaluate.py         # chunking comparison, ablation, threshold sweep -> results/*.csv/png
```
Options: `--mode tfidf|bm25|hybrid`, `--chunker fixed|sentence|section`, `--max-chars`, `--overlap-sents`, `--threshold`.

## Pipeline -> file map
| Requirement | File | What it does |
|---|---|---|
| 1 Ingestion (PDF, DOCX, TXT, PPTX) | `loaders.py` | Extracts (heading, text) sections from all 4 formats |
| 2 Knowledge base + vector-DB workaround | `kb/`, `kb_content.py`, `make_kb.py`, `search.py` | 7 documents; NumPy matrix + metadata list, cached in `index/` |
| 3 Chunking | `chunking.py`, `evaluate.py` (A) | fixed / sentence / section, compared experimentally |
| 4 Embedding | `tfidf.py` | TF-IDF from scratch (+ optional stemming, bigrams) |
| 5 Similarity | `tfidf.py::cosine_sim` | Cosine similarity with NumPy |
| 6 Retrieval | `search.py` | Top 3 chunks + source file + score; threshold = "no answer" |
| 7 Testing | `test_queries.py`, `evaluate.py` | 20 queries: direct, paraphrase, no-match, multi-chunk |

## Design decisions
- **Vector store workaround:** an in-memory `n_chunks x vocab` matrix plus a parallel metadata list, saved as `.npy` + `.json`. At 42 chunks brute-force cosine is instant; this is what a vector DB does minus the infrastructure. (Confirm with your instructor, as the brief asks.)
- **Section-aware metadata:** loaders keep headings separate; chunks are indexed as `heading. text` but displayed without the heading prefix.
- **Chunking:** default is sentence-based, max 250 chars, 1-sentence overlap (see results below). The KB's sections average ~170 characters, so sizes of 150 to 500 are the meaningful range.
- **Hybrid scoring:** `0.7 * TF-IDF cosine + 0.3 * normalised BM25`.
- **Threshold 0.25:** chosen from the sweep in `evaluate.py` (C).

## Results (generated by `evaluate.py`; 17 answerable queries for ranking metrics)

**A. Chunking comparison (plain TF-IDF, no stemming/synonyms)**
| Config | Chunks | Recall@3 | MRR | Coverage |
|---|---|---|---|---|
| fixed 150/0 | 51 | 0.765 | 0.706 | 0.647 |
| fixed 150/40 | 67 | 0.824 | 0.735 | 0.765 |
| fixed 300/60 | 34 | 0.882 | 0.794 | 0.824 |
| fixed 500/100 | 19 | 0.882 | 0.824 | 0.853 |
| sentence 150/1 | 64 | 0.882 | 0.853 | 0.824 |
| **sentence 250/1** | 42 | 0.882 | **0.882** | 0.794 |
| sentence 250/1, no heading | 42 | 0.882 | 0.794 | 0.824 |
| section (per heading) | 38 | 0.882 | 0.853 | 0.824 |

Reading: tiny fixed windows hurt (they cut facts in half). Sentence and section chunking give the best ranking (MRR). Prepending headings lifted MRR from 0.794 to 0.882. Differences between the top configs are small because this KB is small, so treat the choice as "good and justified", not "proven optimal". Fixed 500/100 has the best Coverage but returns larger, less precise chunks.

**B. Feature ablation (sentence 250/1)**
| Config | Recall@3 | MRR | Coverage |
|---|---|---|---|
| TF-IDF baseline | 0.882 | 0.882 | 0.794 |
| + stemming | 0.882 | 0.853 | 0.824 |
| + synonym expansion | 0.941 | 0.941 | 0.882 |
| + bigrams | 0.941 | 0.941 | 0.882 |
| BM25 | 0.941 | 0.941 | 0.882 |
| Hybrid | 0.941 | 0.941 | 0.882 |

**C. Threshold sweep:** 0.20 rejects 2 of 3 no-match queries; 0.25 rejects all 3 while keeping Recall@3 at 0.941; 0.30 starts dropping valid answers (0.706).

## Test summary (20 queries, default system): 17 PASS, 2 PARTIAL, 1 FAIL
Full retrieved chunks are in `results/test_results.md`.
- **Paraphrases** ("time off", "work from home", "harassed", "reward") pass only because of the synonym map. Without it, plain TF-IDF fails them. This is the core limitation of lexical retrieval.
- **No-match:** all 3 return nothing. Without the threshold, "company stock price" matched leave_policy.pdf via the generic word "company".
- **Partial (lose laptop, public Wi-Fi):** the IT chunk is found, but the second source (conduct / remote-work chunk) does not reach the top 3 or falls below threshold.
- **Fail ("first month"):** the slide says "Within 30 Days", and "month" and "30 days" share no tokens.

## Limitations (be upfront in your report)
- The synonym map and the 0.25 threshold were tuned on the same 20 queries, so results are optimistic. For a fair estimate, write 10 new queries after tuning and report them separately.
- Lexical matching cannot capture meaning; dense embeddings would address the "first month" failure.
- The KB is small (42 chunks), so metric differences of one query move numbers by about 6 percentage points.
